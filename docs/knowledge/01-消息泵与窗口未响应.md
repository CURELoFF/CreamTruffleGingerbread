# 01 · 消息泵与窗口未响应

> 上下文：本项目删除 `SDL_PollEvent` 循环后 Windows 800×600 窗口弹出即卡死，被标"未响应"。
> 本文回答三件事：**未响应的机制是什么**、**SDL_PollEvent 到底干了什么**、**这个知识将来还会在哪出现**。

---

## 一、现象回顾

```cpp
while (running) {
    // while (SDL_PollEvent(&event)) {   ← 被注释掉
    //     if (event.type == SDL_EVENT_QUIT) running = false;
    // }
}
```

- 窗口弹出正常；
- 但拖不动、缩放无效、点 X 无效，几秒后 Windows 给标题栏盖"未响应 (Not Responding)"戳；
- **桌面和其他程序一切正常** —— 不是死机，只是这一个窗口所在的线程瘫痪了。

## 二、核心机制：每条窗口线程背着的纪律

Windows 图形环境给**每个拥有窗口的线程**立了一条铁律：

> **你的窗口想活着，就将定期取出你的消息队列。**

操作系统把你窗口上发生的一切——鼠标移动、拖拽、按钮点击、窗口缩放重绘、其他程序对你发的请求——都封装成**消息 (Message)**，塞进你的**消息队列 (Message Queue)**。这个队列不替你读，只收。

你的程序这边就必须有一个循环，不断"取消息 → 按消息内容行动"：

```text
事件队列 (OS 维护)                  你的程序
┌────────────────────┐
│ 消息: 鼠标移动到(x,y) │ ──────>  取出 → 处理
│ 消息: 窗口被拖动      │ ──────>  取出 → 处理
│ 消息: 关闭按钮被点    │ ──────>  取出 → 处理(决定退出?)
│ ...                 │
└────────────────────┘
```

这个"不断取 → 处理"的循环，叫**消息泵 (Message Pump)**。**不泵 = 只进不出 = 队列堵塞 = 无人理睬任何输入 = 未响应。**

## 三、`SDL_PollEvent` 的双重身份

SDL 在你的游戏线程里干了**两件事**，都在 `SDL_PollEvent` 里：

1. **泵系统消息** —— 调用 Win32 的消息泵 APIs（`PeekMessage` 一族），把 Windows 队列里的消息取走；
2. **翻译与转投** —— 把 Win32 消息翻译成跨平台的 `SDL_Event` 塞进 SDL 自己的事件队列，输出给你。

所以：

```
你的 while (SDL_PollEvent(...)) 每转一圈：
  = 替 SDL 泵了一次系统消息    ← 没这一步，窗口"未响应"
  = 可能拿到一个 SDL_Event     ← 有这一步，游戏逻辑能响应输入
```

**两层循环各有使命**：内层把"此刻积压的所有事件"排干（不漏帧），外层为游戏逻辑的每帧 update → render 画大框架。删掉内层，两个使命一起死亡。

## 四、为什么是几秒后、不是当场死

Windows 持续观察每个窗口线程的 pumping 频率。当一个窗口超过若干秒（约 5 秒级别）泵不出消息，OS 才把"未响应"标签贴出去。这也解释了：

- 未响应的**瞬间还有反应**，几秒后彻底瘫痪；
- OS 给你退路（弹"立即结束/等待"对话框），因为你的线程还在转（空转），只是不干正事。

## 五、这个知识将来还会在哪出现（伏笔 🪝)

1. **加载大资源时的窗口变白/未响应** —— 单线程加载几十秒，线程忙于加载、无人泵消息。工业解法：加载放后台线程，主线程继续泵消息，加"假进度条"动画。
2. **游戏内弹出 OS 对话框后卡死** —— 模态对话框自带消息泵挪走了你的泵，需要小心嵌套泵的行为。
3. **写文字/输入框**（IME 拼中文）—— IME 输入与窗口消息队列的交互，背后同一条消息链路。
4. **服务器无窗口程序** —— 没有窗口就不受此律管辖，这也是"游戏服务器常用纯逻辑线程、窗口瘦身在客户端"的一种原因。

## 六、概念词典

| 术语 | 一句话解释 |
| --- | --- |
| **消息 (Message)** | OS 对"发生了什么事"的封装，含类型 + 附加数据 |
| **消息队列 (Message Queue)** | 每条窗口线程一个、OS 维护的收件箱，只进不出除非你取 |
| **消息泵 (Message Pump)** | "取一个消息 → 处理 → 再取" 的循环，GUI 线程的保命律动 |
| **未响应 (Not Responding)** | 窗口线程长期不泵消息时 Windows 贴的警告标签 |
| **PeekMessage / DispatchMessage** | Win32 的消息泵底层 API，SDL 池在它们之上 |
| **SDL_Event** | SDL 把各种 OS 消息翻译成的**跨平台统一事件格式** |
| **SDL_PollEvent** | 双重身份：替你泵系统消息 + 从 SDL 队列给你事件 |

## 七、本篇记忆锚点 🎯

> **GUI 程序的存活不是免费的：每帧的每一次 `SDL_PollEvent`，既是游戏逻辑读输入的入口，也是窗口向操作系统"报平安"的呼吸。**
> 游戏帧循环的骨架 = 泵呼吸 + 推进游戏状态 + 画一帧。
