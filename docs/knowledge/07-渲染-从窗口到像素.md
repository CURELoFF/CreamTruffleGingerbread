# 07 · 渲染：从窗口到像素——SDL_Renderer 与"命令队列"心智模型

> 背景与上下文：窗口已经稳稳地开了、稳稳地关了——但它是一块**黑色（或透明）的空壳**。
> 本课目标：在窗口里画出第一个矩形。同时你会见到 RAII 连击第 3 号（Renderer 类），
> 以及一个能解释"为什么画了却没显示"的心智模型：**命令队列**。

---

## 一、一句话核心

> **Window 是画布的壳；Renderer 是"把你想画的东西变成真实像素"的画笔+画室。**
> 渲染的每一步动作（选色、清屏、画矩形）都只是**录制指令**，
> 唯有 Present（提交）那一刻，指令才被执行、像素才真正上屏。

## 二、地图：一帧渲染的流水线

```text
每帧（Application::Run 的 while 循环里）：
   ① SDL_SetRenderDrawColor    录：选中一支颜色的画笔
   ② SDL_RenderClear           录：用这支颜色把整个画布清一遍
   ③ SDL_SetRenderDrawColor    录：换一支颜色
   ④ SDL_RenderFillRect        录：画一个实心矩形
   ⑤ SDL_RenderPresent        ★交付：以上所有指令此刻才真正变成屏幕像素

  ①~④ 再快也只是"写计划书"，⑤ 才是"把计划书拍在屏幕上"。
```

**为什么这样设计？（408·OS/组成原理 的重要映射点：缓冲与同步）**
屏幕的刷新由显示硬件按节奏进行。如果程序"画一步、屏幕刷一步"，屏幕可能
在**画到一半**时刷新——用户看到撕裂的半张脸。解法：程序先在**离屏缓冲区**
把整帧画完，Present 一次性把成品交给屏幕（双缓冲的朴素形态）。
所以"录一堆指令、最后一次交付"不是性格古怪，是**正确性需求**。

## 三、类要第二次套模板：`core/Renderer`（RAII 连击 №3）

形状和 Window 完全同构：**构造获取、析构释放、禁拷贝、IsValid 查询**，只多一件事——

```cpp
// src/core/Renderer.hpp
#pragma once
#include <SDL3/SDL.h>       // SDL_Renderer、SDL_Window 的类型声明

class Renderer {
public:
    explicit Renderer(SDL_Window* target);      // 出生：在目标窗口上创建渲染上下文
    Renderer(const Renderer&) = delete;
    Renderer& operator=(const Renderer&) = delete;
    ~Renderer();                                // 死亡：SDL_DestroyRenderer

    bool IsValid() const;
    SDL_Renderer* Get() const { return renderer_; }   // ★新面孔：Get 访问器

private:
    SDL_Renderer* renderer_ = nullptr;
};
```

**★新面孔：`Get()` 访问器**——Application 每帧要调用 SDL 的渲染函数，
函数签名要的是 `SDL_Renderer*`，而不是"我们的 Renderer 对象"。
Get() 的职责就是**把内部句柄借给 SDL 用，但所有权始终握在自己手里**。
纪律：只有这种"借出去用、不许持有"的裸句柄访问器可以返回裸指针；
`window_` 那种所有权成员，永远不出门。

```cpp
// src/core/Renderer.cpp
#include "Renderer.hpp"

Renderer::Renderer(SDL_Window* target) {
    renderer_ = SDL_CreateRenderer(target, nullptr);   // 第二参数=驱动名，null=自动选
}

Renderer::~Renderer() {
    if (renderer_) SDL_DestroyRenderer(renderer_);
}

bool Renderer::IsValid() const {
    return renderer_ != nullptr;
}
```

## 四、依赖方向与生命周期嵌套（模块化顺讲的真正舞台）

现在 Application 里要住第三个成员。声明顺序**有讲究**：

```cpp
private:
    Subsystem subsystem_;   // ① 最早出生、最晚死亡
    Window window_;         // ② 需要"子系统已就绪"
    Renderer renderer_;     // ③ 需要"窗口已存在" ← 声明在 window_ 之后
```

两面同时成立：

- **出生方向**：按声明顺序构造——子系统 → 窗口 → 渲染器，每一环的依赖都按时就位；
- **死亡方向**：严格逆序析构——渲染器死（DestroyRenderer）→ 窗口死（DestroyWindow）→ 子系统死（SDL_Quit）。

这就是"依赖方向"的实操版：**被依赖者活得必须比依赖者更久**。
C++ 用"声明顺序 + 逆序析构"让程序员**只改一个排位就同时满足两个方向**——
记住这个模型，将来拼装任何"生命周期嵌套"的资源（音频、字体、纹理……）都是同构题。

## 五、Application 的全部改动（真实三步）

**.hpp 里**：成员区加 `Renderer renderer_;`（含 `#include "Renderer.hpp"`）。

**.cpp 里两处**：

```cpp
// ① 构造函数：初始化列表追加 renderer_
Application::Application(std::string_view title, int width, int height)
    : subsystem_(SDL_INIT_VIDEO),
      window_(title, width, height),
      renderer_(window_.Get()) {}        // 用窗口的句柄出生（Get 第一次上岗）
```

```cpp
// ② Run()：事件循环之后、注释掉的那行空间，正是画第一帧的位置
void Application::Run() {
    bool running = true;
    SDL_Event event;

    while (running) {
        while (SDL_PollEvent(&event)) {
            if (event.type == SDL_EVENT_QUIT) running = false;
        }

        // --- 一帧渲染（录 4 条指令 + 1 次交付） ---
        SDL_SetRenderDrawColor(renderer_.Get(), 32, 32, 48, SDL_ALPHA_OPAQUE);
        SDL_RenderClear(renderer_.Get());
        SDL_SetRenderDrawColor(renderer_.Get(), 230, 120, 70, SDL_ALPHA_OPAQUE);
        SDL_FRect rect{640.0f, 380.0f, 320.0f, 140.0f};   // x, y 是矩形左上角坐标
        SDL_RenderFillRect(renderer_.Get(), &rect);
        SDL_RenderPresent(renderer_.Get());
        // (update → render 分离的完整形态，等输入课成形)
    }
}
```

色彩小知识：参数是 **RGBA 四通道**（红/绿/蓝/透明度，各 0~255）。
`SDL_ALPHA_OPAQUE` = 255 = 完全不透明。32,32,48 是近黑的"夜空蓝"，230,120,70 是橙红。

坐标小知识：原点在**窗口客户区左上角**，x 轴向右、y 轴向下（屏幕坐标系，
与数学课习惯的"y 轴向上为正"正好相反；这也是为什么 SDL 屏幕坐标系"从上往下长"）。

## 六、常见坑

1. **"我 Draw 了但屏幕没变化！"**——九成是忘了 `SDL_RenderPresent`。指令只录不交付 =
   计划书写完没送印。用第二节的心智模型自检：**这帧交付过吗？**
2. **渲染器死得比窗口晚**——如果哪天你乱调成员声明顺序（renderer_ 排到 window_ 前面），
   析构时就会先 DestroyWindow 后 DestroyRenderer，顺序反了。口诀回看第四节。
3. **Surface 与 Renderer 是两条路线**——SDL 传统上还有 `SDL_GetWindowSurface`
   的 CPU 绘制路线。**本项目永远走 Renderer 路线**（GPU 加速 + 命令队列），
   网上教程若出现 UpdateWindowSurface，那是 1.x/2.x 时代混合写法，保持警惕。

## 七、概念词典

| 术语 | 一句话解释 |
| --- | --- |
| Renderer | 渲染上下文：承载"绘制指令 → 像素"的执行者（GPU 后端抽象） |
| 命令队列 | 渲染 API 的组织方式：先录指令，交付时一次性执行 |
| Present | 交付动作：把录好的帧真正送到屏幕 |
| 双缓冲 | 画完整帧再换屏，避免"画到一半被刷新"的撕裂 |
| RGBA | 红/绿/蓝/透明度四通道，各 0~255 |
| SDL_FRect | 矩形：x, y（左上角）+ w, h（宽高），SDL3 渲染用浮点版 |
| 访问器 Get() | 把内部裸句柄"借而不予"地交给第三方 API 用 |
| 生命周期嵌套 | 资源间依赖经声明顺序 + 逆序析构自动满足的模式 |

## 八、记忆锚点 🎯

> Window 是壳，Renderer 是画室；SetColor/Clear/FillRect 全是**录**，
> Present 才是**交**。Get() 借句柄不交所有权，
> 声明顺序定出生、逆序析构定死亡——被依赖者活到最后。
