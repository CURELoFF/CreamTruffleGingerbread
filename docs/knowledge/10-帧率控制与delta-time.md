# 10 · 帧率控制与 delta time：把速度从帧里解放出来

> 背景与上下文：08 课埋的债——`kSpeed = 8.0f`（每帧移动 8 像素）意味着速度
> 同帧率**绑定**：60Hz 屏幕上每秒 480 像素，144Hz 上每秒 1152 像素。
> 同一个游戏在两台机器上完全是两种手感。本课偿还这笔债，
> 同时第一次把 408·OS 的两个主角请上舞台：**高精度时钟**与**线程睡眠**。

---

## 一、一句话核心

> **速度的钱应以"秒"计，干活却以"帧"为单位发生——中间的汇率就是 delta time（dt）。**
> `本帧位移 = 速度（像素/秒） × dt（秒/帧）`；帧率无论如何波动，物理后果不变。

## 二、dt 心智模型：把"每帧"翻译成"每秒"

```text
上一帧心跳 = last        （记这个时刻，单位 = 时钟 ticks）
本帧心跳   = now         （再记这个时刻）
dt（秒）   = (now − last) ÷ 每秒的 tick 数    ← 这就是"汇率"

update 里：位置 += 速度 × dt
  60fps 时：dt ≈ 1/60，一帧走 400 × 1/60 ≈ 6.7 像素
  144fps 时：dt ≈ 1/144，一帧走 400 × 1/144 ≈ 2.8 像素
  → 一秒钟内两种机器都恰好走约 400 像素。帧率变化被汇率自动抹平。
```

**单位纪律**（本课最容易翻车处）：dt 必须 `double` 或 `float`——
用整数存放会全变 0（两帧间隔<1 秒，整数除法取整…整没了）。

**时间从哪来：SDL 的高精度时钟**

```cpp
Uint64 now = SDL_GetPerformanceCounter();       // 从"开机的某个点"数到现在的 tick 数
Uint64 freq = SDL_GetPerformanceFrequency();    // 这台机器上每秒走多少 tick
```

为什么不用"挂钟"（`std::time`/系统日期）？408·OS 的关键概念一对冤家：

| | 墙钟（wall clock） | 单调时钟（monotonic clock）★ 游戏用它 |
| --- | --- | --- |
| 是什么 | 回答"现在几点" | 回答"过了多久" |
| 特征 | NTP 校时会**跳变**（前跳/回拨） | 只前进、不回头的纯流水 |
| 游戏用它的下场 | 用户改时间 → 你的矩形瞬移穿越 | 一切平滑 |

`SDL_GetPerformanceCounter` 就是单调时钟（基于 CPU 计数器，408·组成原理的
时钟中断/计数器同族，精度纳秒级）。

## 三、dt 的三个实战坑（都在你未来的报表里）

1. **首帧的"祖传 last"**——last 必须在**进循环之前**初始化一次；不初始化或
   在循环内才首次赋值，第一帧的 dt 可能是天文数字，矩形开局瞬移出境。
2. **暂停/断点后的 dt 海啸**——调试停在断点十秒钟，恢复后 dt = 10 秒，矩形
   一帧飞出地图（或碰撞判定直接穿过去）。解法：**给 dt 设上限钳制**：
   `dt = std::min(dt, 0.1);`（超过 100ms 的间隔按 100ms 算——牺牲精确换稳定）。
3. **dt 是"上一帧花了多久"，不代表"下一帧将花多久"**——这是它的数学底色
   （外推）。帧率极抖动时会有轻微不匀，进阶解法（固定步长、插值）将来遇到痛点再上。

## 四、限帧：世界不该全速空转

现在 while 循环是**裸奔**：没有渲染同步没有睡眠，一秒能转几千圈、CPU 风扇起飞。
限帧有两个正统姿势：

**姿势 A：垂直同步（vsync）——把游戏节拍器绑到显示器节拍器**

```cpp
// Renderer 构造完渲染器之后立刻设置（出生时配置住处）
SDL_SetRenderVSync(renderer_, 1);   // 1 = 等 1 次 vsync 信号（多数后端支持）
```

原理：显示器按自己的刷新率（常见 60/120/144Hz）往外扫像素；vsync 让 Present
**阻塞到下一次屏扫开始**——游戏循环的节奏自动被显示器拖着走，帧率 = 刷新率，
还顺带消灭"画面撕裂"（上半帧与下半帧来自不同时刻的两帧拼在一起）。

**姿势 B：帧间隔睡眠（frame pacing）**

```cpp
SDL_Delay(剩余时间)   // 把 CPU 让给操作系统：本线程进入"就绪/阻塞"，调度器去跑别人
```

408·OS 的即视感：**sleep 不是 CPU 停了，是本线程让出时间片、回到"阻塞态"**，
由调度器安排他人接棒——忙等（busy-wait）空转烧 CPU 却不出活，才是反面教材
（笔记本电池表示强烈反对）。本项目先上姿势 A（vsync 一行搞定），
B 作为知识储备，将来多线程/音频同步时再精细使用。

**vsync 与 dt 并不冲突**：即便锁了 60fps，仍有掉帧、后台挂起、vsync 不被支持的
情形——dt 依旧是那个"汇率保险"。两者分工：**vsync 管"什么时候交付"，dt 管"交付间隔翻成多少速度"**。

## 五、本课实战蓝图（两文件各一刀）

**① `Renderer.cpp`：构造函数末尾加一行**

```cpp
Renderer::Renderer(SDL_Window* target) {
    renderer_ = SDL_CreateRenderer(target, nullptr);
    SDL_SetRenderVSync(renderer_, 1);   // 出厂即锁帧节拍器（不支持的假性后端会忽略）
}
```

**② `Application.cpp`：Run() 换算心（原有代码保留，只动四处）**

```cpp
void Application::Run() {
    bool running = true;
    SDL_Event event;

    const Uint64 freq = SDL_GetPerformanceFrequency();  // 每秒 tick 数（机器常数）
    Uint64 last = SDL_GetPerformanceCounter();          // 祖传 last：进循环前一次（坑 1 的解药）

    // ……rect 声明不变……

    while (running) {
        while (SDL_PollEvent(&event)) {
            if (event.type == SDL_EVENT_QUIT) running = false;
        }

        // ★ 取出本帧 dt（秒）；钳制上限防断点海啸（坑 2 的解药）
        const Uint64 now = SDL_GetPerformanceCounter();
        double dt = static_cast<double>(now - last) / static_cast<double>(freq);
        last = now;
        dt = std::min(dt, 0.1);

        // ================= update：速度终于按"秒"计 =================
        const float kSpeed = 400.0f;   // 400 像素/秒（按手感调，与帧率无关了）
        if (keys[SDL_SCANCODE_LEFT])  hero.x -= kSpeed * static_cast<float>(dt);
        // ……RIGHT / UP / DOWN 同样乘 dt……
        // ……clamp 与碰撞判定照旧……
        // ……render 照旧……
    }
}
```

（`std::min` 同样住 `<algorithm>`——上一课已 include，白得。`keys` 那行照旧每帧取。）

**自由实验（强烈推荐，视觉化学习使理解加深）**：update 里临时加一行
`std::cout << 1.0/dt << " fps\n"`，跑一次观察数字（约即显示器刷新率），
看完拆掉——这既是限帧的确认，也是 dt 最直观的直尺。

## 六、概念词典

| 术语 | 一句话解释 |
| --- | --- |
| delta time (dt) | 相邻两帧的间隔（秒），帧率的倒数，速度 × 的"汇率" |
| Performance counter | SDL 的高精度单调时钟（tick 计数），游戏时间的正统来源 |
| 墙钟 / 单调钟 | "现在几点"（会跳）/ "过了多久"（只进不退） |
| vsync | 等待显示器扫描信号再交付帧——帧率被锁到刷新率 |
| 画面撕裂 | 一帧画面被硬件扫描时撞上下一帧的提交，上半下半错位 |
| SDL_Delay / 让出时间片 | 线程进入阻塞态把 CPU 还给调度器（408·OS 的运行态→阻塞态） |
| 帧率 vs 刷新率 | 游戏循环的产生速度 / 显示器消费速度，vsync 把二者衔接 |

## 七、记忆锚点 🎯

> 速度计秒，干活计帧，dt 当汇率。单调钟做心跳，墙钟只配报时。
> last 出生在循环前，钳制挡住断点海啸；vsync 管节拍，dt 管折算，
> sleep 是把 CPU 还给世界——不是关机。

## 十一、课后答疑补录：主循环的节奏，闸门在 Present

**Q：dt 的计算影响循环次数吗？帧数浮动在刷新率上，哪个函数在锁节奏？**

五个渲染调用按"阻不阻塞"分两类：SetColor/Clear/FillRect 只是**录指令**，瞬间完成；
**SDL_RenderPresent 在 vsync 开启时会停在原地等待下一次显示器扫描**才返回。
于是主循环的速率被"最慢的阻塞点"决定——闸门就是 Present。

**三条铁律一并入账**：

1. **循环速率 = 其内部最慢阻塞点的速率**（把 vsync 参数改 0 一验即知：闸门立即消失、恢复全速）；
2. **dt 只管"每次循环走多远"，从不参与节奏**——次数由消费端（显示器）通过闸门决定；
3. 将来的"成人式"结构：update 用**累加器按固定频率**分账（严格每秒 N 次），render 随显示器节奏分账（vsync），两者每秒次数**可以不同**（如 update 120 / render 60），两帧之间的画面用**插值**补齐——这就是"两个循环"的初级形态，多线程版（UE 的 GameThread/RenderThread）是其放大版。
