# 04 · C++ 类初见：构造、析构与 explicit——写 Window 前的语法通行证

> 背景与上下文：下一步是 `core/Window.hpp/.cpp` 实战（把 02 课的 RAII 思想变成真代码），
> 但构造函数、析构函数、`explicit`、`~` 这些语法还没建立。本文只覆盖写 **Window 需要的最小语法集**，
> 实战时逐行对照，不在真代码里留下看不懂的断点。

---

## 一、一句话核心

> **类（class）= 一张蓝图，规定对象"长什么样"（数据成员）、"能做什么"（成员函数）、"怎么生怎么死"（构造函数/析构函数）。**
> 02 课说"资源获取写在出生里、释放写在死亡里"——本篇就是这两句话的语法本体。

## 二、蓝图（class）与对象（object）

```cpp
class Window {                      // class = 蓝图；Window = 类型名
public:                             // 此后的成员：外部可见 —— 对外的"接口"
    bool IsValid() const;           // 成员函数（对象具备的能力）
private:                            // 此后的成员：外部不可见 —— 内部状态
    SDL_Window* window_ = nullptr;  // 数据成员（行尾 = nullptr 是 NSDMI，见第七节）
};
```

- 类是蓝图，**对象**是运行时按蓝图造出的具体实例：`Window w("App", 800, 600);` 造出对象 w；
- **访问控制**是封装的大门：外部代码只能通过 public 接口操作 w，胳膊伸不进 private 区——
  内部状态（比如裸指针 `window_`）在语法上就无法被外部滥用；
- UE 对照：你在 UCLASS 里写 private 成员 + Getter，和这是同一件事，只是这次没有引擎代劳，全手写。

## 三、生与死：构造函数与析构函数

**构造函数**：与类同名、**没有返回类型**、在对象出生那一刻被自动调用：

```cpp
class Window {
public:
    Window(std::string_view title, int width, int height);  // 构造函数：与类同名
};
```

**析构函数**：`~` + 类名，**没有参数、没有返回类型**，在对象死亡那一刻被自动执行，且**恰好一次**。
`~` 只是个名字记号，作用是告诉编译器"这是析构函数"：

```cpp
~Window();   // 不可带参数、不可重载，一生只有这一个
```

"死亡"的时机——对于栈上的对象，就是变量**离开作用域**的瞬间：

```cpp
void Demo() {
    Window w("Demo", 800, 600);   // ← 出生：构造函数自动执行
    // ...使用 w 做事...
}                                 // ← 死亡瞬间：~Window() 自动执行，恰好一次
```

于是 02 课的 RAII 承诺有了语法落点：

| RAII 承诺（02 课） | 语法落点（本课） | Window 里写什么 |
| --- | --- | --- |
| 构造时获取资源 | 构造函数 | `window_ = SDL_CreateWindow(...)` |
| 析构时释放资源 | 析构函数 | `SDL_DestroyWindow(window_)` |
| 离开作用域自动释放 | 析构函数**自动调用** | 你一行都不用写，这是编译器的职责 |

## 四、在 .cpp 里定义成员：`类名::` 前缀

03 课说过：成员函数**声明**在类里，**定义**写在 .cpp，两者靠 `类名::` 前缀对上号：

```cpp
// src/core/Window.cpp
#include "Window.hpp"

Window::Window(std::string_view title, int width, int height) {
    window_ = SDL_CreateWindow(title.data(), width, height, SDL_WINDOW_RESIZABLE);
}

Window::~Window() {
    if (window_) SDL_DestroyWindow(window_);
}

bool Window::IsValid() const {   // const 成员函数：承诺"只读不改"（第七节细讲）
    return window_ != nullptr;
}
```

**经典坑**：漏写 `Window::`——编译器会把那一行当作不挂在任何类上的自由函数，
轻则与头文件声明对不上，重则链接期直接 LNK2019（第一课亲手挖过的同款坑，这次你该能自己诊断了）。

## 五、explicit：禁止"隐式变身"

单参数构造函数有一个隐蔽行为——编译器会拿它做**隐式转换**：

```cpp
class Meters {
public:
    Meters(double v);              // 没写 explicit
};

void DrawLine(Meters length);

DrawLine(42.0);          // 😱 编译通过：42.0 被悄悄转换成 Meters(42.0)
DrawLine(Meters{42.0});  // ✅ 显式写明，才该有的样子
```

"编译通过"在这里反而是**坏事**：读代码的人看到的是一个裸的 42.0 变成了 Meters，
转换发生在看不见的地方，语义被稀释了。`explicit` 就是为这个场景准备的开关：

```cpp
class Meters {
public:
    explicit Meters(double v);     // 禁止隐式转换
};

DrawLine(42.0);          // ❌ 编译错误：必须显式构造
DrawLine(Meters{42.0});  // ✅ 唯一合法途径
```

对 Window 的意义：不加 explicit 时，`Window w = {"游戏", 800, 600};` 这种写法也编译通过——
一个窗口被"赋值"成花括号列表，可读性一塌糊涂。加上后只能
`Window w("游戏", 800, 600);`，一眼看清"这里在构造窗口"。

**项目规则**：不希望被隐式调用的构造函数，一律加 explicit。
（UE 对照：UE 编码规范强制单参数构造函数标 explicit——又一个你在 UE 里习以为常的规则，
背后是标准 C++ 的通用道理。）

## 六、`= delete`：把"禁止"变成语法事实

C++ 有个理念：**有些函数你不写，编译器替你生成**。对一个类，若你不声明，
编译器会自动生成：默认构造函数、拷贝构造、拷贝赋值、移动构造、移动赋值、析构函数。

但自动生成有连带规则，现在只需记住两条：

1. **你声明了析构函数 → 移动家族（move）不再自动生成**；
2. 拷贝家族**仍会自动生成**——而我们根本不想要拷贝
   （两个 Window 对象持有同一个 `SDL_Window*`，死亡时双重 `SDL_DestroyWindow` = 双重释放崩溃，02 课的原话）。

所以用 `= delete` 把拷贝明令禁止：

```cpp
Window(const Window&) = delete;             // 拷贝构造：显式删除
Window& operator=(const Window&) = delete;  // 拷贝赋值：显式删除
```

效果：任何拷贝 Window 的尝试**直接编译错误**——02 课"拷贝陷阱"从口头警告升级成语法拦截。
（03 课自测第 3 题的答案就在这两行：第一行删的是拷贝构造，第二行删的是拷贝赋值。）

## 七、三个小说法点（实战会用到）

1. **const 成员函数**：`bool IsValid() const;` 结尾的 const 是函数签名的一部分，
   含义是"这个函数承诺不修改对象状态"——只读能力。对外接口的"查询类"函数都该标。
2. **类内 inline 定义**：把函数体直接写在类声明里，编译器按 inline 处理
   （03 课 ODR 特例的亮相）。短小的 Getter 常这样写，如
   `SDL_Window* Get() const { return window_; }`。
3. **NSDMI（默认成员初始化器）**：`SDL_Window* window_ = nullptr;` 声明行尾的 `= nullptr`，
   保证对象出生的一瞬指针就是空，绝不带着随机垃圾值乱跑；
   构造函数体里立刻赋真值——"先空着、马上填上"，双保险。
   （顺带一提：现代 C++ 还有**成员初始化列表**写法 `Window::Window(...) : window_(x) {}`，
   把"出生后赋值"升级为"出生即初始化"。等实战遇到真正需要它的场景再讲，现在不囤积语法。）

## 八、概念词典

| 术语 | 一句话解释 |
| --- | --- |
| 类（class） | 蓝图：规定数据成员、成员函数，以及对象生死的挂钩点 |
| 对象（实例） | 运行时按蓝图在内存里造出的具体实体 |
| 构造函数 | 与类同名、无返回类型；出生时自动调用，可重载多个 |
| 析构函数 | `~ + 类名`，无参数无返回；死亡时自动执行恰好一次，不可重载 |
| explicit | 禁止该构造函数参与隐式转换，必须显式构造 |
| = delete | 显式删除某函数；任何调用/拷贝尝试直接编译期报错 |
| 访问控制 | public = 对外接口 / private = 内部状态（封装的语法层） |
| 类名:: | .cpp 中定义成员的前缀；漏写即脱离该类的自由函数 |
| const 成员函数 | 结尾 const，承诺只读不改；只读对象上也可调用 |
| 成员初始化列表 | 构造函数参数表后 `:` 开头的列表，"出生即初始化"（暂缓） |
| NSDMI | 声明行尾的 `= 默认值`，保证出生瞬间的确定状态 |

## 九、记忆锚点 🎯

> 蓝图造对象；构造函数管出生、析构函数管死亡——RAII 从此有了语法本体。
> explicit 禁隐式，= delete 禁拷贝；.cpp 里定义成员必须挂 `类名::`，
> 漏写一个前缀，链接器就找不到对上号的兑现。
