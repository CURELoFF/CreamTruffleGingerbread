# 08 · 输入：SDL 键盘事件——让矩形动起来（408·数据结构正式登场）

> 背景与上下文：上一课的矩形固定在 (640, 380)，坐标是**写死的字面量**——它不是活的。
> 本课：读键盘 → 改位置 → 重画。一步不大的改动，从此窗口里有了"会回应你的东西"，
> 而且正式启用一个 408·数据结构的核心武器：**数组**。

---

## 一、一句话核心

> **游戏循环的三拍子正式成立：输入采集 → 状态更新（update）→ 渲染（render）。**
> "会动"的本质是：矩形的位置是**状态**（会变的数字），键盘改变状态，
> 每帧渲染把当前状态画出来——画面只是状态的影子。

## 二、从"写字面量"到"有状态"

上一课 Run() 里的这行：

```cpp
SDL_FRect rect{640.0f, 380.0f, 320.0f, 140.0f};   // 每帧都是同一个值 = 静止的假象
```

它每帧都画在同一个位置——不是"不能动"，是**没有任何东西在改变它**。让它动只需：

1. 把 x/y 当作**会变的量**（rect 是局部变量，本课先就地管理，将来升级为正式的游戏对象）；
2. 每帧**先**读键盘、**后**改 x/y——这一段有个专有名字：**update**；
3. 渲染段照旧把 rect 画出来——**render**。

从此 Run() 里的代码天然分成两段落（这正是原计划"事件循环与游戏帧"一课的内容，
本课顺势合并讲掉）：**update 在前、render 在后，一整圈 = 一帧（frame）**。

## 三、键盘怎么读：SDL3 给的"本帧快照数组"★本课主菜

SDL3 提供两条读键盘的路线：

| 路线 | API | 适用 |
| --- | --- | --- |
| 事件驱动 | `SDL_EVENT_KEY_DOWN / SDL_EVENT_KEY_UP` | 适合"单击、触发一次"（切枪、回车提交） |
| **状态轮询** | `SDL_GetKeyboardState()` | 适合"**持续按住**"（本课的持续移动） ★ |

为什么移动选轮询不选事件？——`KEY_DOWN` 事件只在**按下瞬间**发出（按住不发、
自动重复另说）；"按住 W 不放 → 持续移动"用状态查询天然直给：**每帧问一次"现在还按着吗"**。

```cpp
// SDL_GetKeyboardState 返回一个【数组】的地址：bool 型，下标是"键的编号"（scancode）
const bool* keys = SDL_GetKeyboardState(nullptr);   // 每帧重新拿一次（拿"本帧快照"）

if (keys[SDL_SCANCODE_LEFT])  { /* 左键正被按住 */ }
```

**这里是 408·数据结构的入口，值得慢下来看清楚数组的本质：**

```text
keys[SDL_SCANCODE_RIGHT] 这行代码编译后发生什么？

   数组的真相 = 连续内存 + 一条寻址公式：
   地址 = 基址(keys) + 下标 × sizeof(bool)

   因此 keys[i] 与 i 始终相等，恒定 O(1) 时间取到 —— 数组的招牌性能。
   SDL 给每个物理键编了连续的整数号（SDL_Scancode），恰好"塞进下标"！
   用数组下标编码"键位"是教科书级的技巧：
   —— 10000 把锁一字排开，报号即开门，无需查表、无需遍历。
   （性能视角：整个键位快照几百个 bool，塞在几十字节量级，稳稳住进 CPU 缓存线。）
```

408 对应：**数组随机寻址 O(1)**、连续存储对缓存友好（后续 cpu-cache 课程再来翻倍深挖）。

## 四、本课实战蓝图：只改 Run()（加 1 个 include）

```cpp
void Application::Run() {
    bool running = true;
    SDL_Event event;

    SDL_FRect rect{640.0f, 380.0f, 320.0f, 140.0f};   // 矩形的状态（暂时住 Run 里）

    while (running) {
        while (SDL_PollEvent(&event)) {
            if (event.type == SDL_EVENT_QUIT) running = false;
        }

        // ================= update：读键盘 → 改状态 =================
        const bool* keys = SDL_GetKeyboardState(nullptr);   // 本帧键盘快照
        const float kSpeed = 8.0f;    // 每帧移动 8 像素（临时偷步，见"坑"3）
        if (keys[SDL_SCANCODE_LEFT])  rect.x -= kSpeed;
        if (keys[SDL_SCANCODE_RIGHT]) rect.x += kSpeed;
        if (keys[SDL_SCANCODE_UP])    rect.y -= kSpeed;
        if (keys[SDL_SCANCODE_DOWN])  rect.y += kSpeed;

        // 边界钳制：不许走出窗外（碰撞检测的序曲）
        // SDL_GetWindowSize 用"借来的"窗口句柄查询客户区尺寸（Get() 第二次上岗）
        int winW = 0, winH = 0;
        SDL_GetWindowSize(window_.Get(), &winW, &winH);
        rect.x = std::clamp(rect.x, 0.0f, static_cast<float>(winW) - rect.w);
        rect.y = std::clamp(rect.y, 0.0f, static_cast<float>(winH) - rect.h);

        // ================= render：把状态画出来 =================
        SDL_SetRenderDrawColor(renderer_.Get(), 32, 32, 48, SDL_ALPHA_OPAQUE);
        SDL_RenderClear(renderer_.Get());
        SDL_SetRenderDrawColor(renderer_.Get(), 230, 120, 70, SDL_ALPHA_OPAQUE);
        SDL_RenderFillRect(renderer_.Get(), &rect);
        SDL_RenderPresent(renderer_.Get());
    }
}
```

外加 .cpp 顶部一行 include（`std::clamp` 住在标准库 `<algorithm>` 里，其余头文件全部现成）：

```cpp
#include <algorithm>    // std::clamp：钳制——越界就贴边
```

## 五、概念词典

| 术语 | 一句话解释 |
| --- | --- |
| 帧（frame） | 游戏循环转一圈；一帧 = 事件处理 → update → render → Present |
| update / render | 状态更新段 / 画面绘制段，顺序固定：先 update 后 render |
| scancode | 物理键的整数编号（键盘布局无关），本课用作数组下标 |
| 输入轮询 | 每帧主动查询输入设备状态（对照：事件驱动靠"来件处理"） |
| 快照 | SDL 每帧刷新一次的键盘状态数组，本帧有效 |
| 钳制（clamp） | 把数值"夹"进 [min, max]，出界贴边——最朴素的碰撞响应 |
| O(1) 下标寻址 | 基址 + 下标 × 元素大小，与元素个数无关的恒定耗时 |

## 六、常见坑

1. **"按一下动一点点，想移动必须连打"**——你很可能用了 `SDL_EVENT_KEY_DOWN` 事件
   而不是状态轮询。回顾第三节两条路线的分工。
2. **快照要每帧重新拿**——`keys` 指针指向 SDL 的内部数组，内容**每帧刷新**；
   在循环内重新取指针是最安全姿势（别把它缓存到循环外当"永久有效"）。
3. **速度绑定帧率的偷步**——每帧固定 8 像素意味着：帧率越高跑得越快。
   本文故意先简化，正确解法（按秒计算 delta time）是"帧率控制"课的主菜，先欠着。
4. **update 忘了放 render 前面**——先画再改状态，画面永远慢一拍（表现为"迟滞一帧"）。

## 七、记忆锚点 🎯

> 输入采集 → update 改状态 → render 画影子；一整圈是一帧。
> 持续按住用轮询，单击触发用事件；键盘快照是个数组，
> scancode 当下标，基址 + 下标寻址恒定 O(1)；
> clamp 贴边不出界——这就是最朴素的碰撞。
