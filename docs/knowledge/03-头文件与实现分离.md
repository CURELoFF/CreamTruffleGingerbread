# 03 · 头文件与实现分离——从 UE 经验看 C++ 通用规则

> 背景与上下文：学生用过 Unreal Engine，已形成"头文件写声明、源文件写实现"的肌肉记忆。
> 本文把它说透：这套习惯背后是**编译器如何把多个 .cpp 拼成一个程序**的通用规则，
> 掌握通用规则后，你在任何非 UE 的 C++ 项目里（比如本框架）都能正确地拆文件、写类。

---

## 一、一句话核心

> **头文件 (.hpp/.h) 负责"告诉编译器有什么"；源文件 (.cpp) 负责"告诉编译器怎么做"。**
> 分离的目的不是习惯，而是：① 让别的翻译单元能"看见"你的类/函数；② 同一份实现只编译一次。

## 二、为什么必须有分离？——回看上次提到的一个细节

第二课（构建系统）里说过：**每个 .cpp 是独立的"翻译单元"（Translation Unit）**，编译 .cpp A 时，编译器**完全不知道** .cpp B 里有什么——它们互相是黑盒。那么 A 想使用 B 里的函数怎么办？

答案是两个阶段联手：

```text
编译期（每个 .cpp 独立进行）:
  A 通过 头文件里的"声明" 得知: "有一个函数叫 UpdateEntity, 接受这些参数, 返回这个返回值"
  → A 据此通过类型检查，并在目标文件里留下一个"欠条": "我引用了符号 UpdateEntity, 请链接时解析"

链接期（所有 .obj 聚齐后进行一次）:
  链接器拿着 A 的欠条, 在 B 的 .obj 里找到对应的"兑现"(定义)
  → 上一课我们亲手见过的报错就是这个环节: "LNK2019: 无法解析的外部符号 SDL_main"
```

> 所以还记得吗？之前遇到的 `LNK2019` 正是**声明与定义没对上**在链接期的现身说法。
> 分工记住一句话：**编译期出错的报错来自 cl.exe（带行号），链接期出错的报错来自 link.exe（LNK 开头）**。

## 三、两者（.hpp 与 .cpp）各自有什么、不能有什么

| 内容 | 头文件 (.hpp) | 源文件 (.cpp) |
| --- | --- | --- |
| 类/函数的**声明**（签名） | ✅ | — （继承头文件） |
| **定义**（函数体） | ❌（原则上；特殊模板则相反） | ✅ |
| `using namespace std;` | ❌ **绝不**（会污染所有包含它的文件） | 原则上也少用 |
| 游戏逻辑实现 | ❌ | ✅ |

> "定义"重复出现在多个翻译单元里会触发 **ODR（One Definition Rule，单一定义规则）**，
> 这是很多初学者在头文件里乱写实现的报错根源。

## 四、`#pragma once` 与为什么需要它（对照 UE）

在 UE 里你写 `.h` 文件时，编辑器/generated.h 会帮你处理"重复包含"问题。通用 C++ 的机制是：

```cpp
#pragma once          // 告诉预处理: 这个头文件在一次编译里最多展开一次 (主流写法)
```

或者传统守卫写法（效果等价，多见于老代码/跨平台库）：

```cpp
#ifndef CORE_WINDOW_HPP
#define CORE_WINDOW_HPP
/* 头文件内容 */
#endif // CORE_WINDOW_HPP
```

(两种方式细节差异在"同一文件硬拷贝成两份"等边角情况；本项目统一用 `#pragma once`。)

## 五、UE 经验 ✅ vs 通用 C++ ⚠️ 差异对照表

下面是你"按 UE 习惯写"和"本框架要求写"的差异清单，逐条过：

| 维度 | UE 的做法 | 通用 C++（本框架） |
| --- | --- | --- |
| 头文件后缀 | `.h` | 本项目用 `.hpp` 明确区分"这是 C++ 接口头文件" |
| 生成器托底 | `UCLASS()`/generated.h 自动管理类 | **没有**，一切手写：构造/析构/拷贝规则 |
| 日志、反射宏 | ULOG、反射自动生成 | 没有，需要自己包一层 Logger |
| 模块/插件系统 | Build.cs 声明依赖 | 用 CMake target + `target_link_libraries` 表达依赖 |
| 智能指针 | `TObjectPtr`/UE 自有回收模型 | `std::unique_ptr`/`std::shared_ptr`（配合 RAII） |
| 反射信息 | 头文件含 GENERATED_BODY 等代码 | 头文件就是纯 C++，没有魔法 |
| include 路径 | UE 自动处理绝对路径 | 显式写相对路径或 CMake 注入路径 |

**最关键的一条**：UE 里很多"不精确的写法"也能跑，因为引擎帮你兜底了一大堆（generated.h、Build.cs、反射系统、模块管理）。
在本项目里 **没有那层兜底**，所以 ODR、`using namespace` 污染、include 最小化这些差异之处**就是规则本身**，不是"可以商量"。

## 六、把规则用起来——马上要写的 `core/Window` 长什么样

（先混个眼熟，具体实现下一课写代码）

```cpp
// src/core/Window.hpp —— 只放"声明"
#pragma once            // 这个头文件在一次编译里只展开一次
#include <SDL3/SDL.h>   // 类成员用到 SDL_Window*, 所以这里要包含
#include <string_view>  // 构造参数用 string_view 类型, 也要包含

// 一个拥有 OS 窗口资源的小类 (RAII, 见上一课)
class Window {
public:
    explicit Window(std::string_view title, int width, int height);
    Window(const Window&) = delete;             // 禁用拷贝 (02 课的第五节!)
    Window& operator=(const Window&) = delete;
    ~Window();                                  // 析构 = SDL_DestroyWindow
    bool IsValid() const;                       // 声明: 使用者用来检查
private:
    SDL_Window* window_ = nullptr;              // 私有数据成员
};
```

```cpp
// src/core/Window.cpp —— 放"实现"
#include "core/Window.hpp"      // 对应头文件总在最前

Window::Window(std::string_view title, int width, int height) {
    window_ = SDL_CreateWindow(title.data(), width, height, SDL_WINDOW_RESIZABLE);
}
Window::~Window() {             // 定义 = 具体做什么
    if (window_) SDL_DestroyWindow(window_);
}
bool Window::IsValid() const { return window_ != nullptr; }
```

要点：
1. `.hpp` 不含任何"干什么"；`.cpp` 每个**定义都带 `类名::` 前缀**——告诉 C++ 这是哪个类的成员函数;
2. **include 的是头文件里真正需要的**（`SDL_Window*` 用于成员声明→必须；不写到的就别 include）
   ——这叫 **include 最小化**，直接影响编译速度（头文件循环 include 是新手常见灾难源）；
3. `= delete` 禁用拷贝，把上篇文章里的"拷贝陷阱"防到底。

## 七、概念词典

| 术语 | 一句话解释 |
| --- | --- |
| **翻译单元 (TU)** | 一个 .cpp 预处理完毕的"完整文本"，编译的最小单位 |
| **声明 (Declaration)** | "有这个东西、长这样"，可重复出现，不生成代码 |
| **定义 (Definition)** | "具体怎么实现"，链接器唯一认领的东西 |
| **ODR** | 同一翻译单元中一个非内联符号只能有一个定义 |
| **#pragma once** | 本编译内防止头文件重复展开的编译器扩展 |
| **include 最小化** | 在头文件里只 include "声明用到的"头，能省编译时间 |
| **前向声明 (Forward Declaration)** | 只写 `class MainWindow;` 一行，不 include 整个头，用于打断依赖环（后面实战） |
| **`类名::` 限定** | 在 .cpp 中指出这是哪个类的成员，分离的头/源靠它对上号 |

## 八、本篇记忆锚点 🎯

> 头文件 = 目录页（有什么）；源文件 = 正文书（怎么干）。
> 编译期看声明、链接期对定义；重复定义犯 ODR，include 该省就省。
> UE 给你的"写法印象"都对，只是当时引擎帮你托管了 ODR/generated/依赖声明那三件事——**本框架里那三件事是你的责任**。
