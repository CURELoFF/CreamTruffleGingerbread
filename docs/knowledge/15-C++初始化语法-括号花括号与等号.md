# 15 · C++ 初始化语法：括号、花括号与等号

> 背景：B 阶段写 `Surface` 构造函数时，学生第一次见到
> `Type name(expr)` 这种"变量名后面挂括号"的形状（Python/C# 里没有），
> 于是追问 `int a(1); int a{1}; int a = {1};` 到底都是什么。
> 本文是**语法补给支线**（非路线图正课），编号占用 15，下一课精灵动画顺延为 16。

---

## 一、一句话核心

> C++ 的初始化 = **"用哪种语法糖"**（`()` / `{}` / `=`）**去触发哪种构造规则**。
> 四种写法对 `int` 等价，对类类型才分道扬镳：`explicit`、窄化检查、
> initializer_list 优先级、聚合体填充——差别全在规则里。

## 二、先拆形状：括号属于类型，不属于变量名

```cpp
int a(1);     // 拆开：int[类型]  a[变量名]  (1)[初始化式]
A   a(1);     //      A[类型]    a[变量名]  (1)[初始化式]
```

Python 写 `a = 1`，C# 写 `var a = 1;` 或 `new A(1)`；C++ 允许**省略 `=`、省略 `new`**，
于是"类型 + 变量 + 初始化式"挤成一行，看起来像函数调用——对类类型来说它**确实是**构造函数调用。

## 三、四写法矩阵

| 写法 | 学名 | 能调 explicit 构造 | 关键特点 |
| --- | --- | --- | --- |
| `int a(1);` / `A a(1);` | 直接初始化 | ✅ | 老派；有最烦恼解析陷阱 |
| `int a{1};` / `A a{1};` | 直接列表初始化 | ✅ | 禁窄化、无歧义、支持聚合体 |
| `int a = 1;` / `A a = 1;` | 拷贝初始化 | ❌ | 最接近 C#/Python 直觉 |
| `int a = {1};` / `A a = {1};` | 拷贝列表初始化 | ❌ | 上文两者规则的结合 |

对 `int` 四种完全等价（都是 1）。对类类型，见第五节。

## 四、列表初始化 `{}` 的三条硬规则（为什么现代 C++ 推荐它）

**① 禁止窄化（narrowing）**：把"悄悄截断"升级为编译错误

```cpp
int a(1.9);    // ✅ 通过，a = 1（截断，可能只有警告）
int b{1.9};    // ❌ 编译错误：列表初始化禁止窄化
```

**② 消灭"最令人烦恼的解析"（most vexing parse）**

```cpp
A a(1);    // 声明变量，用 1 构造
A a();     // ⚠️ 不是"空参数构造"！这是【函数声明】：函数 a() 返回 A
A a{};     // ✅ 明确：默认/值初始化对象
```

**③ `initializer_list` 优先匹配**——同一个类型，括号与花括号语义可能完全不同：

```cpp
std::vector<int> v(3);   // 3 个元素，值都是 0（"元素个数"构造）
std::vector<int> v{3};   // 1 个元素，值是 3（initializer_list 构造）
```

规则：类型若有 `std::initializer_list` 构造函数，`{}` 会**优先**选它。

## 五、类类型的分叉：explicit 与拷贝初始化

```cpp
class Surface {
public:
    explicit Surface(std::string_view path);
};

Surface s1("a.png");        // ✅ 直接初始化，explicit 不影响
Surface s2{"a.png"};        // ✅ 直接列表初始化，explicit 不影响
Surface s3 = "a.png";       // ❌ 拷贝初始化：禁止 explicit 隐式转换
Surface s4 = {"a.png"};     // ❌ 拷贝列表初始化：同样禁止
```

**为什么 `explicit` 重要**：

```cpp
void Draw(Surface s);
Draw("a.png");   // 若无 explicit：编译器悄悄构造临时 Surface → 隐蔽 bug
                 // 有 explicit：编译错误，逼你写清楚 Draw(Surface{"a.png"})
```

**拷贝初始化到底发生什么**：构造临时对象 → 拷贝/移动给目标（C++17 起多被省略，
但"禁止 explicit"这条规则照旧）。所以规则不是"性能"而是"**是否允许隐式转换**"。

## 六、聚合初始化：没有构造函数的类/结构体

```cpp
struct Point { int x, y; };        // 聚合体：无自定义构造、无私有成员、无基类…
Point p{1, 2};                     // ✅ 逐成员填充（严格按声明顺序）
Point q(1, 2);                     // ✅ C++20 起也允许（括号聚合初始化）

SDL_FRect r{50.f, 50.f, 100.f, 100.f};   // 项目里天天用：同样是聚合初始化
```

聚合初始化**跳过了构造函数**：没有构造可调，直接按顺序写成员。因此它天然禁止窄化
（`SDL_FRect r{1.5}` 在整数成员上会报错）。

## 七、值初始化 vs 未初始化（`{}` 的隐藏价值）

```cpp
int a;          // ⚠️ 局部变量：未初始化 = 垃圾值（读它是 UB）
int a{};        // ✅ 值初始化：标量归零；类类型调默认构造
int a = 0;      // ✅ 显式归零
```

`T a{};` 是"我想要默认值"的安全写法，也是类成员的推荐初始化方式。

## 八、构造函数初始化列表 ≠ 变量声明（别混淆）

```cpp
class Player {
public:
    Player(float w, float h) : worldW_(w), worldH_(h) {}   // ← 冒号后是初始化列表
private:
    float worldW_;   // 这是成员声明
    float worldH_;
};
```

冒号后的 `member_(expr)` / `member_{expr}` 是**成员初始化**（在进入构造体之前执行，
顺序由成员声明顺序决定，不是书写顺序——04 课的老规矩）。它和变量声明长得很像，
意义完全不同。

## 九、本项目惯例（可背走）

| 场景 | 写法 |
| --- | --- |
| 声明并给初值 | `T a{expr};`（首选） |
| 空对象/默认值 | `T a{};`；🚫 永不写 `T a();` |
| 单参数构造（Surface 收路径） | `explicit T(std::string_view)` + `T s{"path"};` |
| 容器要 N 个元素 | `std::vector<T> v(n)`（括号=个数） |
| 容器要"一个值为 n 的元素" | `std::vector<T> v{n}` |
| 聚合体（SDL_FRect 等） | `SDL_FRect r{x, y, w, h};` |
| 类成员初值 | `int count_{0};` / `InterpProperty<SDL_FRect> rect_{SDL_FRect{...}};` |

## 十、常见坑

1. **`T obj();`** —— 声明了函数而不是对象（most vexing parse）；
2. **`vector<int> v{3}` 以为是 3 个元素** —— 实际是 1 个值为 3 的元素；
3. **列表初始化里做窄化** —— `int x{1.9}` 直接编译错误（这是保护，不是麻烦）；
4. **拷贝初始化用了 explicit 构造** —— `Surface s = "a.png";` 编译失败，改用 `{}` 或 `()`;
5. **读未初始化的局部变量** —— `int a;` 后用 `a`，值是垃圾（UB）；
6. **以为成员初始化列表按书写顺序执行** —— 实际按**声明顺序**（04 课 Rule of 0 相关）；
7. **聚合体用括号乱序填** —— 按成员声明顺序，不按名字（C++20 才有指定初始化 `.x = 1` 的受限支持）。

## 十一、概念词典

| 术语 | 一句话 |
| --- | --- |
| 直接初始化 `T a(x)` | 按重载解析挑构造函数，允许 explicit |
| 拷贝初始化 `T a = x` | 构造临时对象再拷贝/移动，禁止 explicit |
| 列表初始化 `T a{x}` | 优先 initializer_list，禁窄化，无解析歧义 |
| 值初始化 `T a{}` | 标量归零，类类型调默认构造 |
| 聚合初始化 | 无自定义构造的类/结构体逐成员填充 |
| 窄化（narrowing） | 可能丢信息的隐式转换（double→int、long→short…） |
| most vexing parse | `T a();` 被解析成函数声明的经典陷阱 |
| explicit | 禁止构造函数的隐式转换（拷贝初始化会被拒） |
| initializer_list | 花括号初始化的优先匹配目标（容器/字符串常见） |
| 成员初始化列表 | 构造函数冒号后 `member_(x)`，按声明顺序执行 |

## 十二、记忆锚点 🎯

> 括号直接建，等号拷贝建，花括号全能且更严（禁窄化、无歧义、优先 initializer_list）。
> `T a();` 是函数不是对象；`vector<T> v(n)` 是 n 个元素、`v{n}` 是 1 个元素。
> 聚合体按声明顺序填；explicit 挡隐式转换；`T a{}` 空对象最安全。
